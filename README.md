# Datalab Kit

Однократный установщик 12 независимых пакетов для **Pi coding agent**. Пакет: `@dev-sergeev/datalab-kit`; история выпусков — в [CHANGELOG](CHANGELOG.md).

## Установка 0.2.2

Нужны Node.js ≥ 24 и установленный `pi`; `permission-system` 1.0.2 указывает peer-зависимости Pi `^1.5.0`. Kit не устанавливает и не обновляет сам Pi и не закрепляет его версию.

**После публикации 0.2.2 под отдельным dist-tag `installer`:**

```bash
npx @dev-sergeev/datalab-kit@installer
pi
```

По умолчанию установка глобальная для каталога агента Pi, в том числе заданного через `PI_CODING_AGENT_DIR`. Для установки в текущий проект:

```bash
npx @dev-sergeev/datalab-kit@installer --local
```

Локальная установка использует штатные проверки доверия Pi. Установщик не передаёт `--approve` и не разрешает доверие за пользователя.

Не используйте `pi install npm:@dev-sergeev/datalab-kit` для 0.2.2: Kit больше не является runtime-пакетом Pi. Отдельный CLI вызывает штатный `pi install` для каждого отсутствующего компонента и показывает ход установки; после ошибки запуск завершается, а следующий продолжает незавершённую установку. Тег `installer` не меняет `latest`: последний опубликованный `latest` — 0.1.8, а 0.2.1 не публиковалась.

**До публикации**, из исходников:

```bash
npm ci --ignore-scripts --legacy-peer-deps
npm run build
node scripts/install.mjs
```

Последняя команда действительно устанавливает пакеты. Для разработки используйте одноразовую копию проекта и изолированный каталог агента через `PI_CODING_AGENT_DIR`, а не рабочую конфигурацию.

Отсутствующие компоненты подключаются как npm-источники **без версии**, например `npm:@dev-sergeev/pi-recap`: начальную версию определяет npm `latest`. Уже настроенные источники, закреплённые версии и фильтры ресурсов сохраняются без замены.

Kit не включает код компонентов, не патчит их, не задаёт значения их настроек и не загружается в сессии Pi. Доработки recap принадлежат отдельному готовому форку `@dev-sergeev/pi-recap`; остальные компоненты подключаются под своими исходными именами. Команды, модели, разрешения и настройки описаны в документации самих пакетов; ссылки — в [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md).

## После первоначальной установки

Состав больше не синхронизируется с Kit. Штатные команды Pi управляют компонентами независимо:

```bash
pi list
pi update npm:permission-system
pi uninstall npm:pi-rewind
```

`--local` выбирает проектную область для установки и удаления, но не для `pi update`. Если один пакет зарегистрирован глобально и в доверенном проекте, обновление может затронуть обе записи. `pi update` не снимает закрепление версии.

Повторный запуск установщика, новая версия Kit или его повторная загрузка **не восстанавливают** удалённые компоненты, не обновляют оставшиеся и не добавляют новые пакеты будущего состава. Установщик хранит состояние первоначальной установки отдельно от собственного npm-пакета и отдельно для глобальной и проектной областей. Пока установка не завершена, повторный запуск продолжает её; после завершения это no-op.

Маркер состояния — `.datalab-kit-install.json` в каталоге агента для глобальной установки или в `<проект>/.pi` для локальной. **Не удаляйте маркер:** это сбрасывает память об установке и может восстановить намеренно удалённые компоненты. После принудительного завершения процесса может остаться каталог блокировки `.datalab-kit-install.json.lock`; удалять только эту блокировку можно лишь убедившись, что установщик больше не запущен.

## Permission system и переход с 0.2.1

Новый состав использует `npm:permission-system`; документация и настройки пакета — на [npm](https://www.npmjs.com/package/permission-system). Upstream запрещает одновременно загружать его с `npm:@gotgenes/pi-permission-system` или `npm:@mzwing/pi-permission-auto-review`.

Перед новой или незавершённой установкой проверьте `pi list` и удалите конфликтующий источник из каждой области, где он зарегистрирован: глобальной и текущего проекта. Используйте точный источник из списка, например `pi uninstall npm:@gotgenes/pi-permission-system`, а для проекта — `pi uninstall npm:@gotgenes/pi-permission-system --local`; аналогично удаляется `npm:@mzwing/pi-permission-auto-review`. После этого повторите запуск установщика в нужной области. До удаления конфликта незавершённая установка останавливается без установки компонентов и записи состояния.

Завершённая установка 0.2.1 остаётся нетронутой: повторный запуск 0.2.2 ничего не меняет и не заменяет старый пакет. Чтобы перейти на новый, пользователь должен сам удалить конфликтующий источник в соответствующей области и установить `pi install npm:permission-system` (для проекта добавить `--local`). Нельзя включать старый и новый пакеты одновременно. Ни установщик, ни эти инструкции не требуют удаления пользовательской конфигурации или правил разрешений; совместимость сохранённых настроек проверяйте по документации upstream.

## Переход с 0.1.x

Запустите новый CLI в той же области установки, предварительно устранив конфликты permission system, как описано выше. Он однократно добавит отсутствующие компоненты, сохранив существующие источники, pins (включая старые версии GigaChat), фильтры ресурсов и прочие настройки. После успешного подключения компонентов штатный `pi uninstall` удаляет старый источник самого Kit. Не запускайте Pi между шагами миграции: до её завершения старый Kit ещё может загружать собственную систему разрешений. Самостоятельные пакеты, пользовательские файлы, навыки, конфигурация и авторизация не удаляются.

Сохранённые старые pins компонентов могут быть несовместимы с актуальным Pi. Kit не снимает их автоматически: совместимую версию в таком случае выбирает пользователь.

Если при продолжении прерванной установки источник уже появился, но Kit не записал владение этим незавершённым шагом, он сохраняется как пользовательский. Один суффикс `@latest` не даёт установщику права его переписывать.

**Поведение изменилось:** `permission-system`, Plan Mode и Subagents работают по собственным правилам и сохранённым настройкам. Прежние автоматические разрешения чтения и todo, обход дополнительных подтверждений в Plan Mode и лимит одного субагента больше не задаются Kit. Удалены провайдер `DataLab` из `GIGACHAT_API_URL`/`JPY_API_TOKEN`, встроенные навыки `init`/`skill-creator` и их короткие команды. Пользовательские копии навыков вне пакета сохраняются.

Вместо `@tifan/pi-recap`, ранее встроенного в Kit, устанавливается `@dev-sergeev/pi-recap`. Независимо установленный пользователем `@tifan/pi-recap` не удаляется: проверьте `pi list`, чтобы не загружать два recap одновременно.

Архитектура и причина отдельного CLI: [ADR 0004](docs/adr/0004-independent-component-installer.md). Старые ADR и записи changelog описывают соответствующие исторические версии, а не правила 0.2.2.

## Разработка и границы проверки

После установки dev-зависимостей и сборки:

```bash
npm run typecheck
npm test
```

Архив 0.2.2 проверен на macOS arm64 с Node.js 26.11.0, npm 12.2.1 и Pi 1.6.0. CLI установил из публичного npm все 12 пакетов в изолированный профиль. SDK загрузил и привязал все расширения без ошибок; зарегистрированы `/permission-system` и `/permission-auto-review`. npm заблокировал нативный install-скрипт `tree-sitter-bash`; поставляемый WASM-парсер разобрал тестовую команду без разрешения этого скрипта.

Модельные запросы, интерактивный TUI и другие платформы не проверялись.
