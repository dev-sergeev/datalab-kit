# Datalab Kit

Готовый набор дополнений для **Pi coding agent**, опубликованный как `@dev-sergeev/datalab-kit`. История выпусков — в [CHANGELOG](CHANGELOG.md).

## Установка

Нужны Node.js ≥ 22.19 и установленный Pi. Совместимость проверяется с Pi 0.85.1.

```bash
pi install npm:@dev-sergeev/datalab-kit
pi
```

После публикации первая команда устанавливает весь набор. До публикации можно проверить локальный архив:

```bash
npm ci --ignore-scripts --legacy-peer-deps
npm run build
npm pack
pi install ./dev-sergeev-datalab-kit-0.1.3.tgz
```

Целевые системы — Linux и macOS; локальные интеграционные проверки выполнены на Linux. Проверка macOS включена в CI. Windows пока не заявляется.

## Значения по умолчанию

- Чтение файлов, просмотр каталогов и поиск разрешены в любых папках.
- Служебный `todo` создаёт и обновляет список задач сессии без подтверждения.
- Читающие цепочки вроде `grep foo *.ts | head`, регулярные выражения, комментарии, чтение через `<`, объединение stderr со stdout и вывод в `/dev/null` не требуют подтверждения. У команд с изменяющими опциями шаблоны файлов разрешаются с фиксированным префиксом пути или после `--`, когда это исключает внедрение опций из имён файлов.
- Изменения через `write`, `edit`, `npm install`, `git commit` требуют подтверждения.
- Неизвестные команды и любой удалённый `curl` требуют штатного подтверждения. Распознанные удаления, Hadoop/HDFS и опасный SQL проходят отдельное усиленное согласование.
- `curl` к `localhost`, `127.0.0.1` и `::1` разрешён только для GET/HEAD. Для автоматически разрешённых запросов отключаются `.curlrc` и прокси; перенаправления, вывод в файл и изменяющие запросы требуют подтверждения.
- Составная команда проверяется целиком. `cat a > b` требует штатного подтверждения; `find . -delete` — усиленного. Неизвестный shell-синтаксис сохраняет штатный путь.
- Обычные подтверждения показывает штатный диалог `@gotgenes/pi-permission-system`: разрешение одного запуска или на сессию, отказ и отказ с причиной. Его настройки клавиш и повторного нажатия сохраняются. Отдельный красный блок Datalab Kit применяется только к защищённым вызовам.
- Одновременно работает один субагент. Инструмент `subagent` принимает одну задачу за вызов.

Уже заданные пользователем настройки имеют приоритет над значениями по умолчанию, включая обычные разрешения, настройки штатного диалога и число субагентов. Исключение: `allow`, YOLO и сессионные разрешения не отменяют усиленное согласование; применимый `deny` окончателен. Значения разрешений и числа субагентов действуют в памяти. Настройки разрешений остаются в штатных `extensions/pi-permission-system/config.json` внутри каталога агента и `.pi/extensions/pi-permission-system/config.json` внутри проекта. Субагенты используют `<agentDir>/subagents.json` и `<project>/.pi/subagents.json`.

В **Plan mode** допустимость инструментов и команд определяет действующий pi-plan-mode, включая пользовательские настройки. Запрещённый вызов блокируется до ввода `yes`; допустимый защищённый вызов всё равно требует усиленного согласования. Для остальных допустимых вызовов сохраняется прежнее поведение без дополнительных подтверждений набора: явные пользовательские `ask` и `deny` продолжают действовать, некорректная конфигурация не обходится. После выхода из Plan mode или перехода к реализации правила набора снова действуют. Это поведение сохраняется при восстановлении сессии и смене ветки. Plan mode допускает некоторые тесты и проверки, которые могут создавать артефакты.

## Усиленное согласование опасных команд

| Группа | Когда требуется точное `yes` |
| --- | --- |
| Локальное удаление | `rm`, `rmdir`, `unlink`, `find -delete`, известные вложенные удаления, любой `git clean` без доказанного dry-run, удаления и удаление исходных файлов в `rsync`. `git clean` защищён даже без `-f`: настройки Git могут отключать требование force. Реальные dry-run формы не считаются удалением. |
| Hadoop/HDFS | Любой вызов `hadoop` или `hdfs`, включая просмотр и чтение. |
| SQL через bash | `psql`, `beeline`, `hive`, `spark-sql`: изменение данных, схемы или прав, в том числе `DELETE`, `DROP`, `TRUNCATE`, `INSERT`, `UPDATE`, либо SQL с неизвестным эффектом. |

Известные shell-обёртки, командные подстановки и вызываемые функции разбираются, а не проверяются поиском слов. SQL анализируется в командных аргументах, файлах, stdin, startup/init и include-источниках. Встроенные shell/DFS вызовы тоже учитываются. Непрочитанный или неизвестный SQL-вход поддерживаемого клиента требует усиленного согласования.

Учитываются известные исполнители вроде `sudo`, `command`, `flock`, `watch`, `parallel`, `xargs` и `fd`. Неизвестный аргумент не скрывает известный опасный executable. Генерируемые аргументы заданий и неизвестный рабочий каталог делают SQL-эффект неизвестным, даже если видимый `-c` содержит `SELECT`.

Для veto используются нормализованные пути, в том числе явно заданный Git work-tree и простые quoted ссылки на известные значения переменных. Это дополнительные evidence для запретов: они не раскрывают динамический executable и не превращают неизвестный SQL/флаг dry-run в доказанно безопасный.

Перед вводом проверяются применимые конфигурационные запреты команд и путей и настоящая политика Plan mode. При разрешённом вызове появляется крупный **красный встроенный блок**, не modal/overlay: полный вызов, причины, инициатор и рабочий каталог. Введите ровно `yes` и нажмите Enter. `Yes`, `yes ` и пустой Enter не одобряют; Esc или Ctrl-C отменяют. Длинный текст просматривается **Ctrl+PgUp/PgDn**: обычные PgUp/PgDn в fullscreen Pi заняты прокруткой чата.

Одно одобрение относится к одному полному неизменённому вызову инструмента. Оно не сохраняется на сессию; при следующем опасном вызове нужно новое `yes`. После одобрения или отказа штатного второго диалога, judges или записи решения в pi-permission-system нет. Запреты повторно проверяются после ожидания ответа.

Запросы субагентов, в том числе вложенных и из другого процесса, передаются живой человеческой родительской сессии. Родительский `allow`/YOLO, judge и UI самого субагента не заменяют ответ человека. При отсутствии доступного родителя или UI вызов блокируется; RPC клиент должен поддерживать текстовый `ui.input`. Одновременные запросы последовательно занимают один inline-ввод.

**Граница защиты:** это слой согласования, не sandbox. Непрозрачные скрипты, Python и динамические имена исполняемых команд остаются на прежнем штатном пути; другие SQL-клиенты и MCP не входят в SQL-покрытие. Явный ручной bash пользователя также сохраняет прежнее поведение. Доверенными считаются расширения, клиент/launcher и SQL-клиент/сервер: расширение может исполнять код вне tool hooks, а SQL-функция или view на сервере может иметь скрытый эффект. Файлы, окружение и состояние сервисов не снимаются в immutable snapshot: одобрение связывается с вызовом, а не с неизменностью всех его источников и целей.

Реализацией владеет набор: `src/enhanced-{classifier,sql,policy,runtime,ui}.ts`; интеграция — проверяемая адаптация `scripts/prepare-upstream.mjs`, независимый bootstrap — `src/security-extension.ts`. Это не fork с собственным развитием библиотеки. Поддерживается только встроенный `@gotgenes/pi-permission-system` **33.0.5**, протокол адаптера **1**. Отсутствующий адаптер, неподдерживаемая версия или неполная интеграция блокируют **все агентские инструменты**, а не возвращают небезопасный fallback. Не обновляйте встроенную библиотеку отдельно: новая версия принимается через обновление набора, адаптацию и проверки. См. [ADR 0003](docs/adr/0003-enhanced-dangerous-approval.md).

## Recap, время работы и навыки

`/recap` показывает краткое резюме сессии над редактором. При первом подключении набора в `<agentDir>/extensions/pi-recap.json` задаётся `"model": "gigachat/Qwen3.5-397b"`, если явный выбор отсутствует. Существующее поле `model` и остальные поля конфига сохраняются; некорректный конфиг не исправляется автоматически. Выбор можно изменить через `/recap config`, проверить через `/recap status`. Пункт `Use default` сразу возвращает Qwen: сборка адаптирует встроенный default модели. Для Qwen нужна аутентификация GigaChat и endpoint с поддержкой этой модели.

Recap не передаёт уровень reasoning; адаптер GigaChat использует `off`. Явные параметры тела запроса в настройках провайдера могут его переопределить. Таймаут запроса — штатные 4 секунды: конфиг recap его не меняет, а `GIGACHAT_TIMEOUT` не переопределяет явно заданный расширением лимит. Автоматическое резюме создаётся после 5 минут бездействия. Модель основной сессии выбирается независимо.

`elapsed` показывает время полного запроса в индикаторе `Working...`, включая все шаги агента и вызовы инструментов. Счётчик обнуляется для следующего запроса и исчезает после завершения. Работает только в TUI, не заменяет powerline footer и не требует настройки.

`/toggle-skills` управляет видимостью навыков для модели. Изменения сохраняются в `disable-model-invocation` внутри `SKILL.md`; после сохранения выполните `/reload`. Общие навыки в `~/.agents/skills` изменяются и для других агентов, учитывающих этот флаг. Расширение сканирует стандартные каталоги навыков; навыки из npm-пакетов и произвольных путей настроек не перечисляются.

Введите `$` для выбора навыка через `pi-mention-skill`. Скрытый от модели навык остаётся доступен через явное `$имя-навыка`. По умолчанию `/skill:*` скрываются из slash autocomplete; настройки самого расширения сохраняют приоритет над штатными значениями.

## YOLO

YOLO управляется штатным `@gotgenes/pi-permission-system`: откройте `/permission-system` → **YOLO mode** или задайте `"yoloMode": true` в конфигурации расширения. Собственные сессионные команды `/yolo on|off|status`, добавленные в 0.1.1, удалены в 0.1.2.

YOLO автоматически разрешает обычные `ask`. Усиленное согласование опасных команд остаётся обязательным; применимые `deny` и ограничения Plan mode сохраняются.

## Обновление и ограничение Pi 0.85.1

После первого запуска Pi:

```bash
pi update --extensions
```

GigaChat обновляется независимо от версии набора. Обычный запуск Pi не обращается к реестру npm и не устанавливает обновления.

**Известное отклонение от спецификации:** Pi 0.85.1 перезаписывает список пакетов из своего кеша после `npm postinstall`. Поэтому отдельная запись GigaChat для штатного обновления восстанавливается при первом запуске Pi. Между установкой набора и первым запуском `pi update --extensions` не гарантирует обновление GigaChat при неизменной версии набора. Для полного выполнения этого требования нужна поддержка со стороны Pi; установленный Pi пакет не изменяет. Подробнее: [ADR](docs/adr/0002-package-delivery.md).

Явно закреплённый пользователем источник GigaChat сохраняется. При удалении набора отдельная запись GigaChat остаётся; её можно удалить стандартным `pi remove npm:@dev-sergeev/pi-gigachat`. Установка с `-l` пока не проверена.

Отдельная запись GigaChat загружается как самостоятельный пакет со своей политикой. В версии 0.4.0 он устанавливает основную модель Qwen при первой активации версии; это поведение самого провайдера, независимо от настройки recap. Datalab Kit не переписывает исходники самостоятельно установленного GigaChat.

## Разработка

```bash
npm ci --ignore-scripts --legacy-peer-deps
npm run build
npm run typecheck
npm test
```

`build` применяет проверяемые адаптации к локальным permission-system, plan-mode, subagents и значению default-модели recap перед упаковкой. Номера версий и единственность каждого места изменения проверяются; несовпадение завершает сборку с ошибкой. Адаптации не меняют глобально установленные пакеты. Интеграционный тест использует изолированный каталог агента и локальный реестр npm, устанавливает настоящий архив штатной командой Pi и проверяет штатное обновление.

Тесты запускаются последовательно с `--liftoff-only`, чтобы оптимизирующая компиляция WASM-парсера bash не исчерпывала память в ограниченной среде CI. Параметр относится к тестовому процессу; запуск пользователя не меняется.
