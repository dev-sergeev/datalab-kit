# Datalab Kit

Однократный установщик 12 независимых пакетов для **Pi coding agent**. Пакет: `@dev-sergeev/datalab-kit`; история выпусков — в [CHANGELOG](CHANGELOG.md).

## Установка 0.2.1

Нужны Node.js ≥ 22.19.0 и установленный `pi` из последнего стабильного выпуска Pi (`latest`). При подготовке релиза актуален Pi 1.5.2; границы выполненной проверки описаны ниже. Datalab Kit не устанавливает и не обновляет сам Pi.

**После публикации 0.2.1:**

```bash
npx @dev-sergeev/datalab-kit
pi
```

По умолчанию установка глобальная для каталога агента Pi, в том числе заданного через `PI_CODING_AGENT_DIR`. Для установки в текущий проект:

```bash
npx @dev-sergeev/datalab-kit --local
```

Локальная установка использует штатные проверки доверия Pi. Установщик не передаёт `--approve` и не разрешает доверие за пользователя.

Не используйте `pi install npm:@dev-sergeev/datalab-kit` для 0.2.1: Kit больше не является runtime-пакетом Pi. Отдельный CLI вызывает штатный `pi install` для каждого отсутствующего компонента и показывает ход установки; после ошибки запуск завершается, а следующий продолжает незавершённую установку.

**До публикации**, из исходников:

```bash
npm ci --ignore-scripts --legacy-peer-deps
npm run build
node scripts/install.mjs
```

Последняя команда действительно устанавливает пакеты. Для разработки используйте одноразовую копию проекта и изолированный каталог агента через `PI_CODING_AGENT_DIR`, а не рабочую конфигурацию.

| Самостоятельный пакет |

| `pi-powerline-footer` |

| `pi-toggle-skills` |
| `@zigai/pi-mention-skill` |

Отсутствующие компоненты подключаются как npm-источники **без версии**, например `npm:@dev-sergeev/pi-recap`: начальную версию определяет npm `latest`. Уже настроенные источники, закреплённые версии и фильтры ресурсов сохраняются без замены.

Kit не включает код компонентов, не патчит их, не задаёт значения их настроек и не загружается в сессии Pi. Доработки recap принадлежат отдельному готовому форку `@dev-sergeev/pi-recap`; остальные компоненты подключаются под своими исходными именами. Команды, модели, разрешения и настройки описаны в документации самих пакетов; ссылки — в [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md).

## После первоначальной установки

Состав больше не синхронизируется с Kit. Штатные команды Pi управляют компонентами независимо:

```bash
pi list
pi update npm:@dev-sergeev/pi-recap
pi uninstall npm:pi-rewind
```

Для локальных компонентов используйте соответствующую область Pi (`--local`). Если источник закреплён на версии, `pi update` сохраняет pin; смена закрепления — явное решение пользователя.

Повторный запуск установщика, новая версия Kit или его повторная загрузка **не восстанавливают** удалённые компоненты, не обновляют оставшиеся и не добавляют новые пакеты будущего состава. Установщик хранит состояние первоначальной установки отдельно от собственного npm-пакета и отдельно для глобальной и проектной областей. Пока установка не завершена, повторный запуск продолжает её; после завершения это no-op.

Маркер состояния — `.datalab-kit-install.json` в каталоге агента для глобальной установки или в `<проект>/.pi` для локальной. **Не удаляйте маркер:** это сбрасывает память об установке и может восстановить намеренно удалённые компоненты. После принудительного завершения процесса может остаться каталог блокировки `.datalab-kit-install.json.lock`; удалять только эту блокировку можно лишь убедившись, что установщик больше не запущен.

## Переход с 0.1.x

Запустите новый CLI в той же области установки. Он однократно добавит отсутствующие компоненты, сохранив существующие источники, pins (включая старые версии GigaChat), фильтры ресурсов и прочие настройки. После успешного подключения компонентов штатный `pi uninstall` удаляет старый источник самого Kit, чтобы прежние встроенные расширения больше не загружались. Самостоятельные пакеты, пользовательские файлы, навыки, конфигурация и авторизация не удаляются.

Сохранённые старые pins компонентов могут быть несовместимы с актуальным Pi. Kit не снимает их автоматически: совместимую версию в таком случае выбирает пользователь.

Если при продолжении прерванной установки источник уже появился, но Kit не записал владение этим незавершённым шагом, он сохраняется как пользовательский. Один суффикс `@latest` не даёт установщику права его переписывать.

**Поведение изменилось:** оригинальные permission-system, plan-mode и subagents работают по собственным правилам и сохранённым настройкам. Прежние автоматические разрешения чтения и todo, обход дополнительных подтверждений в Plan mode и лимит одного субагента больше не задаются Kit. Удалены провайдер `DataLab` из `GIGACHAT_API_URL`/`JPY_API_TOKEN`, встроенные навыки `init`/`skill-creator` и их короткие команды. Пользовательские копии навыков вне пакета сохраняются.

Вместо `@tifan/pi-recap`, ранее встроенного в Kit, устанавливается `@dev-sergeev/pi-recap`. Независимо установленный пользователем `@tifan/pi-recap` не удаляется: проверьте `pi list`, чтобы не загружать два recap одновременно.

Архитектура и причина отдельного CLI: [ADR 0004](docs/adr/0004-independent-component-installer.md). Старые ADR и записи changelog описывают соответствующие исторические версии, а не правила 0.2.1.

## Разработка и границы проверки

После установки dev-зависимостей и сборки:

```bash
npm run typecheck
npm test
```

Релиз находится на проверке. На macOS arm64 с Node.js 26.11.0 и Pi 1.5.2 выполнена реальная установка всех 12 пакетов из публичного npm через `scripts/install.mjs` в изолированный каталог агента. Сессия SDK `createAgentSession` загрузила и привязала все 12 расширений без ошибок (`extensionsResult.errors = []`); доступны команды `gigachat`, `permission-system`, `recap` и инструменты `subagent`, `ask_user_question`, `todo`. Команды Kit `init`/`skill-creator` и модель DataLab отсутствуют; запуск сессии не изменил источники пакетов.

Эта проверка не включала модельные запросы или взаимодействие с TUI и не доказывает совместимость всех функций компонентов либо других платформ.
