# ADR 0002: Доставка компонентов и значений по умолчанию

Status: accepted for implementation; known spec gap remains

## Контекст

Требуется один пакет Pi с восемью компонентами, фиксированными версиями семи компонентов и независимо обновляемым GigaChat. Пользовательские настройки важнее значений набора (ADR 0001).

Pi 0.85.1 загружает ресурсы из `pi.extensions`, но не применяет конфиги из зависимостей. Его установщик сохраняет кешированный список `settings.packages` после npm lifecycle. Штатное обновление пропускает пакет с неизменной версией и не обновляет его транзитивные зависимости.

## Решение

Семь фиксированных компонентов поставляются через `bundleDependencies` и явно перечисленные ресурсы. Сборка адаптирует два компонента: permission-system получает нижний слой значений набора и диалог с отменой по умолчанию; subagents получает значение `maxConcurrent = 1`. Пользовательские слои остаются выше; файлы конфигурации не переписываются. Изменения исходников воспроизводимы и проверяют версию и уникальность места изменения.

Дополнение от 2026-10-02: схема доставки распространяется ещё на четыре фиксированных компонента — recap, elapsed, toggle-skills и mention-skill (всего одиннадцать). Recap получает Qwen через свой штатный конфиг при отсутствии явного выбора модели. Сборка также меняет только встроенное значение default-модели, чтобы штатный `Use default` возвращал Qwen без перезапуска; таймаут сохраняется. При подключении GigaChat самим набором используется экспорт `gigachatProvider`, чтобы standalone-обработчик провайдера не менял выбранную основную модель.

GigaChat остаётся зависимостью `latest`. При явной установке postinstall проверяет актуальную версию, устанавливает её в управляемый каталог Pi и добавляет незакреплённый источник. При первой активации расширение восстанавливает запись, которую установщик Pi мог затереть; загрузка не выполняет сетевых запросов. До появления отдельной записи провайдер подключается через расширение набора. После её появления его загружает Pi самостоятельно.

## Последствия и пределы

- После первой активации работает штатное `pi update --extensions`, даже если версия набора не изменилась.
- Обновление до первой активации не выполняет требование спецификации об независимо обновляемом GigaChat. Это открытый дефект совместимости с Pi; спецификация не ослабляется.
- Полное решение требует изменения установщика Pi: сохранить добавленные lifecycle источники либо поддержать декларацию зависимых пакетов / hook обновления. Пакет не патчит установленный Pi и не запускает фоновый процесс изменения настроек.
- Исходные конфиги и явно закреплённые источники пользователя сохраняются.
- Отдельный GigaChat остаётся после удаления набора. Очистка, `-l` и существующие независимые установки других компонентов не определены спецификацией.
