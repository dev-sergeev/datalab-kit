# ADR 0003: Отдельный провайдер DataLab из окружения

Status: accepted for implementation

В `pi-gigachat` 0.6.1 `/gigachat` — интерактивный мастер, а не программный интерфейс настройки через аргументы. Для подключения из окружения Datalab Kit владеет отдельным нативным провайдером с идентификатором и именем `DataLab`, повторно используя публичный stream/adapter upstream. Штатная точка входа GigaChat, мастер, сохранённые подключения и настройки пользователя остаются без изменений; код upstream не патчится и мастер не автоматизируется.

Провайдер регистрируется только при непустых после trim `GIGACHAT_API_URL` и `JPY_API_TOKEN` в окружении процесса Pi. URL задаёт корень API, включая нужный префикс вроде `/v1`, без `/chat/completions`; токен передаётся как Bearer и не сохраняется в `auth.json` или настройках. Окружение задаётся до запуска Pi, `.env` автоматически не загружается, новые значения требуют перезапуска. Регистрация не проверяет сервер и не выполняет пробных генераций: ошибки возвращаются при обычном запросе пользователя.

Datalab Kit задаёт только дополнительный фиксированный каталог: `glm-5.2 [DataLab]` (ID `glm-5.2`, контекст 200000, вывод 64000) и `Qwen3.5-397b [DataLab]` (ID `Qwen3.5-397b`, контекст 262144, вывод 32768), с reasoning maps соответствующих моделей upstream 0.5.1. Регистрация не выбирает текущую модель и не меняет сохранённые defaults.

Компромисс: набор отвечает за этот фиксированный каталог и совместимость с публичным адаптером, зато не зависит от автоматизации интерактивного мастера, не хранит секреты и не вводит собственный транспорт. Это ограниченно пересматривает запрет собственной политики моделей из [ADR 0002](0002-package-delivery.md) только для дополнительного DataLab; штатное поведение upstream и независимые настройки recap остаются вне этого пересмотра.

Уточнение от 2026-10-21: начиная с Datalab Kit 0.1.8 публичный адаптер GigaChat 0.6.5 собирается в `dist/gigachat-stream.js` вместе с необходимыми MIT-licensed helpers. Библиотечный код upstream не изменяется; это не собственный транспорт. Сборка нужна, потому что root-алиас pi-ai в загрузчике Pi 0.85.1 не разрешает глубокие импорты библиотечного адаптера в изолированной установке. DataLab использует версию адаптера из релиза набора, а не независимо переопределённую пользователем версию standalone-пакета GigaChat. В тот же модуль включён публичный default-экспорт для первой активации, чтобы не выполнять прямой native-импорт `extension.ts` из `node_modules`; отдельный пакет по-прежнему загружается самим Pi.
