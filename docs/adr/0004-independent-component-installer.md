# ADR 0004: Однократный установщик самостоятельных компонентов

Status: accepted for implementation in 0.2.1; supersedes ADR 0002 and ADR 0003

Datalab Kit больше не владеет runtime-кодом, настройками или патчами компонентов. Выбраны самостоятельные оригинальные пакеты и готовый форк `@dev-sergeev/pi-recap`, подключаемые без версий штатным `pi install`; существующие источники, pins, фильтры и настройки не заменяются. Это позволяет пользователю независимо обновлять и удалять компоненты, но отменяет прежние defaults Kit, собственный DataLab и встроенные навыки.

Вместо `pi install npm:@dev-sergeev/datalab-kit` используется отдельный CLI `npx @dev-sergeev/datalab-kit` (после публикации). В Pi 1.5.2 внешний установщик сохраняет кешированный список пакетов после npm lifecycle: добавление компонентов из postinstall может быть затёрто. CLI запускает завершённые штатные команды последовательно вне этого lifecycle; сам Kit не регистрируется как runtime-пакет, не имеет runtime peer-зависимостей и не устанавливает либо обновляет Pi. Цель совместимости — установленный пользователем стабильный Pi `latest`; совместимость проверяется перед выпуском.

Первоначальная установка сохраняет очередь незавершённых действий и отметку завершения вне npm-пакета отдельно для глобальной и проектной областей. Ошибка оставляет возможность продолжения; после завершения повторный запуск ничего не синхронизирует, даже после удаления компонента или изменения будущего состава Kit. Это намеренный отказ от постоянного reconciliation ради пользовательского контроля. Локальная установка не обходит доверие Pi и не передаёт `--approve`.

При миграции с 0.1.x устанавливаются только отсутствующие компоненты. Только после их успешной установки старый источник Kit удаляется штатным `pi uninstall`, чтобы исключить загрузку прежнего bundled runtime. Пользовательские файлы, копии навыков, настройки и авторизация не удаляются; независимо установленные пакеты, включая старый `@tifan/pi-recap`, не очищаются автоматически.
