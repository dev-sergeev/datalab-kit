# Datalab Kit 0.2.1: самостоятельные готовые пакеты

Состояние: реализовано; проверки и двухосевой code-review завершены в описанных ниже границах. Публикация не выполнялась.

## Цель пользователя

Datalab Kit устанавливает готовые пакеты одной командой, не дорабатывая их внутри набора. После первоначальной установки пользователь независимо управляет компонентами штатными средствами Pi.

## Согласованная архитектура

- После публикации команда — `npx @dev-sergeev/datalab-kit`; проектная область — `npx @dev-sergeev/datalab-kit --local`. Нужен установленный `pi` в `PATH`. CLI также поддерживает `--help`/`-h`; неизвестные аргументы отклоняются.
- Команда `pi install npm:@dev-sergeev/datalab-kit` заменена отдельным CLI, а не оставлена альтернативой. Kit не регистрируется как runtime-пакет Pi; нет postinstall, собственных расширений, bundled компонентов, runtime-зависимостей или peer-зависимостей Pi SDK.
- Цель совместимости — последний стабильный Pi (`latest`), а не строго 0.85.1. Kit сам не устанавливает и не обновляет Pi. Для актуального Pi требуется Node.js ≥22.19.0; dev-зависимости трёх Pi SDK заданы как `latest`.
- Установщик последовательно вызывает публичный `pi install` для отсутствующих компонентов. Источники npm не содержат версии: начальную версию определяет `latest`, последующее обновление выполняет пользователь через `pi update`.
- Существующие пользовательские источники, pins, фильтры ресурсов и прочие настройки сохраняются, в том числе прежние pins GigaChat. Kit не переводит их на `latest` и не переустанавливает уже настроенный компонент.
- Глобальная область — каталог агента Pi (`PI_CODING_AGENT_DIR` либо стандартный `~/.pi/agent`); локальная — `.pi` текущего проекта. Локальное доверие проверяется штатным Pi; Kit не передаёт `--approve`.
- CLI показывает прогресс и ошибки штатных команд. При ошибке установка прекращается и может быть продолжена следующим запуском.
- В каждой области очередь незавершённых действий и отметка завершения хранятся вне установленного npm-пакета Kit: `<agentDir>/.datalab-kit-install.json` глобально либо `<проект>/.pi/.datalab-kit-install.json` локально. Прерванный запуск продолжает сохранённую очередь, не трогая уже завершённые компоненты, даже если пользователь затем их удалил. Маркер не удалять: его сброс может восстановить намеренно удалённые компоненты.
- Источник, появившийся во время прерванной установки без записанного владения незавершённым шагом Kit, считается пользовательским и сохраняется. Установщик не выводит право менять источник из одного лишь суффикса `@latest`.
- После успешного завершения повторный запуск, новая версия либо повторная загрузка Kit — no-op: удалённые компоненты не восстанавливаются, версии не меняются, новые компоненты будущего состава автоматически не добавляются.
- Блокировка — каталог `.datalab-kit-install.json.lock` рядом с маркером. После принудительного завершения процесса он может остаться; удалять только блокировку можно лишь после проверки, что установщик больше не запущен, сохраняя сам маркер.
- При миграции с 0.1.x однократно подключаются только отсутствующие компоненты. После успешной установки компонентов старый npm-источник Kit удаляется через штатный `pi uninstall`, чтобы прежний bundled runtime не загружался. Kit не обновляется и не добавляется обратно как пакет Pi.
- Пользовательские файлы, копии навыков вне пакета, конфигурация и авторизация не удаляются. Самостоятельно установленный `@tifan/pi-recap` не удаляется автоматически; пользователь должен учитывать возможную одновременную загрузку двух recap.

4. `npm:@gotgenes/pi-permission-system`

Оригинальные permission-system, plan-mode и subagents используются без патчей Kit. Доработки готового форка recap принадлежат самому `@dev-sergeev/pi-recap`, а не установщику.

## Изменения поведения при миграции

- Удаляются собственная политика разрешений чтения и todo, интеграция с Plan mode и значение одного субагента. Действуют upstream-поведение компонентов и сохранённые настройки.
- Удаляются собственный провайдер `DataLab`, фиксированный каталог моделей и обработка `GIGACHAT_API_URL`/`JPY_API_TOKEN` со стороны Kit. Это не изменение исходников или настроек самостоятельного GigaChat.
- Исключаются встроенные `init`, адаптированный `skill-creator` и короткие команды Kit. Пользовательские копии вне пакета сохраняются.
- Удаляются специальная обвязка регистрации/первой загрузки GigaChat, сборка его публичных экспортов и локальные патчи компонентов.

## Наблюдения при подготовке 0.2.1

- Метаданные npm показали Pi latest 1.5.2, `@dev-sergeev/pi-gigachat` latest 0.7.7 и `@dev-sergeev/pi-recap` latest 0.4.8. Это наблюдения, не pins релиза и не доказательство runtime-совместимости.
- Для `@dev-sergeev/pi-recap` подтверждён репозиторий https://github.com/dev-sergeev/pi-recap.
- В Pi 1.5.2 внешний `pi install` сохраняет кешированный список пакетов после npm lifecycle. Записи самостоятельных компонентов, добавленные из postinstall, могут быть затёрты. Поэтому согласован CLI вне lifecycle, а не восстановление источников при старте сессии.
- Ранее изученная документация Pi 1.4.0 описывает сохранение versioned npm pins при update; для обычного независимого обновления начальные источники должны оставаться без версий.

## Выполненная реальная проверка 0.2.1

- Среда: macOS arm64, Node.js 26.11.0, Pi 1.5.2, изолированный каталог агента в `/tmp`.
- Собственный `scripts/install.mjs` установил все 12 компонентов из публичного npm с актуальными `latest`.
- SDK `createAgentSession` загрузил и привязал все 12 расширений; `extensionsResult.errors = []`.
- Зарегистрированы команды `gigachat`, `permission-system`, `recap` и инструменты `subagent`, `ask_user_question`, `todo`. Команды Kit `init`/`skill-creator` отсутствуют; модели DataLab нет.
- Запуск сессии не изменил источники пакетов.
- `npm run build` и `npm run typecheck` завершились успешно; целевые регрессии установки, восстановления и сохранения пользовательских источников прошли.
- Выполнены независимые Standards- и Spec-review. Выявленные ошибки выбора первоначального latest, GitHub shorthand и владения временным источником исправлены; повторные review не оставили открытых замечаний.
- Финальный полный запуск `npm test`: 11 тестов пройдено, 0 ошибок.
- Модельные запросы и взаимодействие с TUI не выполнялись. Проверки не подтверждают все функции upstream-компонентов или другие платформы.


## Исторически проверенные факты о 0.1.8

Это описание исходного состояния, а не архитектуры или результатов проверки 0.2.1:

- На момент исследования `package.json` содержал 0.1.8. В наборе было 12 расширений; `scripts/prepare-upstream.mjs` изменял permission-system, plan-mode, subagents и recap.
- GigaChat имел отдельную обвязку установки, регистрации источника и первой загрузки; публичные экспорты собирались внутри Kit.
- Изолированный запуск старого набора через `createAgentSession` с двумя переменными окружения зарегистрировал `DataLab/glm-5.2` и `DataLab/Qwen3.5-397b` без ошибок загрузки расширений. Это не проверка нового релиза или сервера.
- Набор включал `init`, адаптированный Anthropic `skill-creator` и собственные короткие команды.
- Peer-зависимости старого Kit требовали строго Pi 0.85.1, тогда как recap 0.4.8 декларировал диапазоны Pi ≥0.87.1. На раннем этапе исследования latest Pi был 1.4.0, GigaChat — 0.7.2; эти значения заменены более поздними наблюдениями выше.
- Запуск CLI Pi 1.4.0 с `--help` подтвердил команды install/update/uninstall и alias uninstall/remove. Это не интеграционная проверка 0.2.1.

## Согласованные проверки перед выпуском

Проверены публичные CLI Pi `install`/`update`/`uninstall` и загрузка сессии Pi с изолированным каталогом агента; автоматические CLI-регрессии используют локальный npm-реестр. Подтверждены независимое обновление и удаление компонентов, отсутствие восстановления после завершения, продолжение прерванной установки, миграция старого Kit и сохранность пользовательских источников, pins, фильтров и настроек.

До публикации запуск из исходников:

```bash
npm ci --ignore-scripts --legacy-peer-deps
npm run build
node scripts/install.mjs
```

Последняя команда имеет реальные эффекты установки; использовать одноразовую копию проекта и изолированный `PI_CODING_AGENT_DIR`, не рабочую конфигурацию.

Команды проверок разработки после установки dev-зависимостей и сборки:

```bash
npm run typecheck
npm test
```
