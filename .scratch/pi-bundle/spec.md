# Требования к Datalab Kit

Документ фиксирует согласованные ответы Q1–Q21. Предложения из Q22–Q24 остались без ответа и не являются принятыми требованиями. Технический способ реализации выбирается отдельно и должен обеспечивать описанное поведение.

## Согласованная цель

Публичный npm-пакет `@dev-sergeev/datalab-kit` устанавливается поверх базовой конфигурации Pi coding agent командой `pi install npm:@dev-sergeev/datalab-kit`. Состав определяет автор проекта; дополнительные пакеты по инициативе агента не добавляются.

Эта команда устанавливает набор и применяет его значения по умолчанию. Отдельная команда установки или настройки набора в основном сценарии не требуется.

## Согласованный состав

1. `@dev-sergeev/pi-gigachat` — использовать последнюю доступную версию без фиксации конкретного номера.
2. `@juicesharp/rpiv-ask-user-question@2.11.0` — вопросы пользователю.
3. `pi-powerline-footer@0.17.2`.
4. `@gotgenes/pi-permission-system@33.0.5` — требуется дополнительная настройка: чтение любых файлов в любых каталогах не требует подтверждения (`read`, `ls`, `grep`, `find`, `cat` и аналогичные операции). Опасные команды требуют явного подтверждения; подробности ниже.
5. `@narumitw/pi-plan-mode@0.58.3`.
6. `@gotgenes/pi-subagents@21.7.5` — за один вызов инструмента запускается один субагент; одновременно может работать только один субагент. Мультивызов инструментов на данный момент не поддерживается.
7. `@capdiem/pi-todo@0.3.2`.
8. `pi-rewind@0.5.0`.

Все восемь компонентов включены по умолчанию. За исключением явно согласованных в этой спецификации изменений, сохраняются исходные настройки авторов пакетов.

## Модель и доступ к GigaChat

GigaChat добавляется как доступный провайдер, но установка не меняет текущие провайдер и модель пользователя. Пользователь выбирает GigaChat после настройки доступа.

## Поддерживаемые системы

Первый выпуск поддерживает Linux и macOS. Поддержка Windows может быть заявлена после отдельной проверки.

## Политика разрешений

- Чтение любых файлов в любых каталогах разрешено без подтверждения.
- `rm`, `hadoop`, `hdfs`, `curl` к адресам вне localhost и другие команды, способные изменять внешние сервисы, требуют явного подтверждения пользователя.
- Изменения локальных файлов и проекта требуют подтверждения, включая `write`, `edit`, `npm install` и `git commit`.
- Запросы к localhost разрешаются без подтверждения только для получения данных; изменяющие запросы требуют подтверждения.
- Диалог опасной команды заметно выделяется. Варианты в порядке сверху вниз: «Отмена», «Разрешить один раз». По умолчанию выбрана «Отмена», простой Enter отменяет команду. Для разрешения необходимо перейти стрелкой вниз и нажать Enter.
- Опасные команды подтверждаются при каждом запуске; разрешение на всю сессию для них не предлагается.

Исключение для чтения относится к действию целиком: `find` с удалением файлов или `cat` с перенаправлением в файл не являются чистым чтением. Принадлежность команды к `hadoop` или `hdfs` сама по себе требует подтверждения, даже если конкретная подкоманда читает данные.

## Приоритет настроек

Datalab Kit задаёт значения по умолчанию. Уже заданные пользовательские настройки имеют приоритет над значениями набора, включая политику разрешений и настройки субагентов.

## Обновление GigaChat

Нужно использовать последнюю доступную версию GigaChat при установке набора или явном обновлении пакетов, без фиксации номера в Datalab Kit и без ожидания нового выпуска Datalab Kit. Запуск Pi сам по себе не проверяет и не устанавливает обновление.

Обновление выполняется стандартной командой Pi `pi update --extensions`, отдельная команда обновления Datalab Kit не требуется.

## Критерии приёмки

Проверки поведения по умолчанию выполняются без пользовательских переопределений. Сохранение пользовательских настроек проверяется отдельно.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Установка основной командой поверх базовой конфигурации Pi | Все восемь компонентов доступны и включены; значения по умолчанию применены |
| Пользователь заранее настроил совпадающий параметр | Его значение сохраняется и имеет приоритет |
| Чтение файла в проекте или вне проекта, просмотр каталога, поиск без изменения данных | Подтверждение не запрашивается |
| Изменение файла через `write` или `edit`, `npm install`, `git commit` | Требуется подтверждение |
| `rm`, `hadoop`, `hdfs` или команда изменения внешнего сервиса | Требуется явное подтверждение |
| Получение данных через `curl` с localhost | Подтверждение не запрашивается |
| Изменяющий запрос к localhost или любой `curl` вне localhost | Требуется подтверждение |
| Enter сразу после открытия диалога опасной команды | Команда отменена и не выполняется |
| Стрелка вниз, затем Enter в этом диалоге | Разрешён только текущий запуск |
| Повторный запуск опасной команды после предыдущего разрешения | Появляется новое подтверждение |
| Работа субагентов с настройками набора по умолчанию | Одновременно работает не более одного субагента; один вызов инструмента запускает одного агента |
| Установка при уже выбранной пользователем модели | Текущие провайдер и модель сохраняются |
| Вышла новая GigaChat, версия Datalab Kit не изменилась; выполнено явное обновление | Установлена последняя GigaChat |
| Обычный запуск Pi | Автоматическое обновление GigaChat не выполняется |
| Основной сценарий на Linux и macOS | Установка и согласованное поведение работают |

## Не определено в этом обсуждении

Следующие пункты не превращаются в дополнительные требования или согласованные решения:

- Поведение при уже установленном компоненте другой версии: предложение сохранить его из Q22 осталось без ответа.
- Удаление добавленных компонентов и настроек при удалении набора: предложение из Q23 осталось без ответа.
- Поддержка проектной установки через `pi install -l`: предложение из Q24 осталось без ответа. Обязательный согласованный сценарий — исходная команда установки.
- Подробный сценарий настройки учётных данных GigaChat и способ отключения отдельных компонентов.

Способ подключения пакетов, доставки значений по умолчанию и адаптации диалога — задачи реализации. Известные технические ограничения записаны в [технических заметках](technical-notes.md).
