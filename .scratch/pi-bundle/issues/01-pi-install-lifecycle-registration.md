# Сохранить регистрацию GigaChat при первой установке Pi

## Требование

Спецификация требует обновлять GigaChat стандартной `pi update --extensions` независимо от версии Datalab Kit, в том числе непосредственно после установки набора.

## Воспроизведение

1. На Pi 0.85.1 установить `npm:@dev-sergeev/datalab-kit`.
2. Не запускать сессию Pi.
3. Опубликовать новую GigaChat при неизменной версии набора.
4. Выполнить `pi update --extensions`.

GigaChat может остаться на старой версии: `installAndPersist` записывает кешированный список пакетов после npm postinstall, затирая регистрацию отдельного источника. Обновление неизменившегося набора пропускается и его транзитивные зависимости не обновляются. Интеграционный тест фиксирует это поведение на настоящем CLI Pi с локальным npm-реестром.

## Обход в реализации

Первая сессия регистрирует установленную GigaChat без сети. После этого штатное обновление работает. README и ADR 0002 прямо указывают отклонение от спецификации; требование не считается выполненным полностью.

## Для полного исправления

Нужна поддержка Pi: сохранение добавленных npm lifecycle источников либо декларативные зависимые пакеты / hook обновления. Изменение глобально установленного Pi и фоновое редактирование пользовательских настроек не применяются. Следующий выпуск, заявляющий полное соответствие, должен проверить обновление до первой сессии и macOS.
