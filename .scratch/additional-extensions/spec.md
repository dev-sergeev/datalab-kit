# Дополнительные расширения Datalab Kit

Состояние: реализовано и проверено; первоначальная реализация разрешена вызовом `$implement` от 2026-10-02. Решения о моделях пересмотрены и реализация разрешена в grilling-сессии от 2026-10-12; актуальный контракт и проверка recap приведены ниже. Исторические результаты — в `verification.md`, двухосевое ревью — в `review.md`.

## Запрошенный состав

- `@tifan/pi-recap`
- `@pi-plugins/elapsed`
- `pi-toggle-skills`
- `@zigai/pi-mention-skill`

## Согласованные решения

### Штатное поведение GigaChat

Datalab Kit не меняет базовое поведение `pi-gigachat`. При подключении самим набором вызывается штатная точка входа расширения, сохраняющая `/login`, мастер `/gigachat`, встроенные модели и собственную политику назначения основной модели. Требование не добавлять встроенные модели отменено уточнением пользователя от 2026-10-12. Независимые установки GigaChat не изменяются; зависимость остаётся `latest`.

### Модель recap

Назначение конкретной Qwen со стороны Datalab Kit отменено. По согласованию от 2026-10-14 recap без отдельного конфига использует текущую модель основной сессии при каждом запросе; явный выбор через `/recap config` приоритетен. `Use default` немедленно возвращает наследование. При отсутствии текущей модели или её авторизации запрос не подменяется другой моделью. Набор не создаёт и не дополняет конфиг recap; уже сохранённые настройки, включая прежнее назначение Qwen, не очищаются.

### Проверка наследования модели сессии

Историческая проверка от 2026-10-12 установила отсутствие наследования: при основной `glm-5.2` recap использовал Qwen, а после удаления прежней адаптации — фиксированный OpenAI default. Решение «только зафиксировать результат» пересмотрено пользователем 2026-10-14: наследование реализовано. Настоящий `/recap` отправил запрос текущей `glm-5.2`, получил и отобразил ответ локального HTTP endpoint через 4,5 секунды; `reasoning_effort` был `off`, а thinking основной сессии остался `high`. Регрессионные тесты покрывают смену модели между запросами, приоритет явной настройки и немедленный возврат к наследованию через picker.

### Таймаут recap

Таймаут увеличен до 60 секунд; задержка автоматического recap сокращена с 5 до 2 минут по дополнительному запросу пользователя. Runtime-проверка с управляемыми таймерами подтвердила отсутствие запроса на 119 999 мс и автоматический запрос с отображением резюме на 120 000 мс. Recap не передаёт reasoning, что подтверждено для GigaChat как `off` при обычных параметрах провайдера. Произвольные провайдеры и переопределения тела запроса не дают универсальной гарантии отключения reasoning. После изменения задержки сборка и все 9 тестов additional-extensions прошли; ранее прошли typecheck и все 46 тестов. Реальный удалённый endpoint и обмен OAuth-токенами не проверены.

### Управление навыками

Оставляем штатное поведение `pi-toggle-skills` (ответ пользователя от 2026-10-02): переключение видимости меняет `disable-model-invocation` непосредственно в `SKILL.md`, включая общие каталоги навыков. Изменения сохраняются между сессиями и применяются после `/reload`. Скрытие от модели не должно запрещать явный ручной вызов навыка; совместимость ручного вызова через `$skill` проверяется вместе с `pi-mention-skill`.

Собственный слой настроек для изолированного от других агентов переключения навыков не создаём.

## Проверенные факты (2026-10-02)

- По npm registry доступны `@tifan/pi-recap` 0.4.7, `@pi-plugins/elapsed` 0.1.1, `pi-toggle-skills` 0.1.20, `@zigai/pi-mention-skill` 0.10.4.
- В опубликованном `@tifan/pi-recap` 0.4.7 модель хранится в `$PI_CODING_AGENT_DIR/extensions/pi-recap.json`, поле `model`. Штатное значение по умолчанию — `openai-codex/gpt-5.6-luna`.
- В `src/index.ts` recap задаёт `RECAP_REQUEST_TIMEOUT_MS = 4_000` и передаёт его как `timeoutMs`. Настройки этого таймаута в конфиге расширения нет. Задержка автоматического recap после бездействия — отдельный параметр, не таймаут запроса.
- В опубликованном `@dev-sergeev/pi-gigachat` 0.4.0 HTTP timeout вычисляется как `options.timeoutMs ?? Number(env.GIGACHAT_TIMEOUT ?? 300) * 1000`: увеличение переменной окружения не переопределяет переданные recap 4 секунды.
- ID модели Qwen у провайдера — `gigachat/Qwen3.5-397b`. Адаптер при отсутствии `options.reasoning` формирует уровень `off`; параметры тела запроса могут его переопределять. Работа на реальном endpoint не проверена.
- `elapsed` использует `ctx.ui.setWorkingMessage`, считает время полного запуска агента на один запрос и не заменяет footer. Вне TUI таймер не запускается.
- API Pi 0.85.1 содержит `setWorkingMessage`, `addAutocompleteProvider` и `getCommands`, используемые новыми расширениями. Это предварительная проверка API, не подтверждение полной runtime-совместимости.

## Согласованный объём реализации

- Четыре расширения включаются в распространяемый Datalab Kit, с фиксированными версиями и явными ресурсами по схеме ADR 0002.
- `elapsed` и `pi-mention-skill` используют штатные значения по умолчанию. `$` открывает выбор навыков, `/skill:*` скрывается из slash autocomplete; явные пользовательские настройки сохраняются.
- Проверки: загрузка всех четырёх расширений на Pi 0.85.1; сохранение явно выбранной модели recap и существующих настроек; штатная загрузка GigaChat; таймер полного запроса и восстановление рабочего индикатора; переключение видимости навыка после `/reload` и его явный вызов через `$`.
- Если доступ к реальному Qwen endpoint отсутствует, проверка реального recap отмечается как невыполненная, отдельно от офлайн-проверок.

Источники: npm registry и опубликованные tarball указанных версий; [recap](https://github.com/tifandotme/pi-extensions/tree/master/packages/pi-recap), [pi-gigachat](https://github.com/dev-sergeev/pi-gigachat).

## Границы проверок

Согласованный объём проверяется через интерфейсы Pi: загрузку ресурсов пакета, команды и события расширений, локальный HTTP endpoint провайдера и изолированные пользовательские конфиги. Эти границы используются для TDD; приватные функции сторонних расширений не подменяются.
