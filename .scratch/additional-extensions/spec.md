# Дополнительные расширения Datalab Kit

Состояние: реализовано и проверено; реализация разрешена вызовом `$implement` от 2026-10-02. Результаты — в `verification.md`, двухосевое ревью — в `review.md`.

## Запрошенный состав

- `@tifan/pi-recap`
- `@pi-plugins/elapsed`
- `pi-toggle-skills`
- `@zigai/pi-mention-skill`

## Согласованные решения

### Модель recap

Qwen без reasoning из `pi-gigachat` используется как значение по умолчанию для recap. Явно выбранная пользователем модель recap сохраняется (ответ пользователя от 2026-10-02; соответствует ADR 0001). Это требование относится к recap, а не к переключению модели основной сессии.

Проверки реализации: при отсутствии явного выбора recap использует Qwen с выключенным reasoning; существующий выбор модели остаётся неизменным после установки, запуска и обновления набора.

### Таймаут recap

Оставляем штатный таймаут 4 секунды без изменения кода, задающего этот лимит. Пользователь ожидает, что Qwen укладывается в него (ответ от 2026-10-02). Это рабочее допущение, а не результат замера. При подключении проверяем генерацию recap; увеличение таймаута не входит в согласованный объём.

### Сброс модели recap

Ревью выявило, что одного конфига недостаточно для требования о Qwen по умолчанию: штатный пункт `/recap config` → `Use default` удаляет конфиг и немедленно возвращает hardcoded-модель OpenAI. Чтобы согласованное значение работало и после сброса, сборка меняет только provider/id встроенного default в recap 0.4.7, проверяя версию и единственность места изменения. Picker, сохранение пользовательского выбора, генерация и таймаут остаются штатными. Регрессионная проверка использует настоящий picker и `/recap` в той же сессии без `/reload`.

### Управление навыками

Оставляем штатное поведение `pi-toggle-skills` (ответ пользователя от 2026-10-02): переключение видимости меняет `disable-model-invocation` непосредственно в `SKILL.md`, включая общие каталоги навыков. Изменения сохраняются между сессиями и применяются после `/reload`. Скрытие от модели не должно запрещать явный ручной вызов навыка; совместимость ручного вызова через `$skill` проверяется вместе с `pi-mention-skill`.

Собственный слой настроек для изолированного от других агентов переключения навыков не создаём.

## Проверенные факты (2026-10-02)

- По npm registry доступны `@tifan/pi-recap` 0.4.7, `@pi-plugins/elapsed` 0.1.1, `pi-toggle-skills` 0.1.20, `@zigai/pi-mention-skill` 0.10.4.
- В опубликованном `@tifan/pi-recap` 0.4.7 модель хранится в `$PI_CODING_AGENT_DIR/extensions/pi-recap.json`, поле `model`. Штатное значение по умолчанию — `openai-codex/gpt-5.6-luna`.
- В `src/index.ts` recap задаёт `RECAP_REQUEST_TIMEOUT_MS = 4_000` и передаёт его как `timeoutMs`. Настройки этого таймаута в конфиге расширения нет. Задержка автоматического recap после бездействия — отдельный параметр, не таймаут запроса.
- В опубликованном `@dev-sergeev/pi-gigachat` 0.4.0 HTTP timeout вычисляется как `options.timeoutMs ?? Number(env.GIGACHAT_TIMEOUT ?? 300) * 1000`: увеличение переменной окружения не переопределяет переданные recap 4 секунды.
- ID модели Qwen у провайдера — `gigachat/Qwen3.5-397b`. Адаптер при отсутствии `options.reasoning` формирует уровень `off`; параметры тела запроса могут его переопределять. Работа на реальном endpoint не проверена.
- `elapsed` использует `ctx.ui.setWorkingMessage`, считает время полного запуска агента на один запрос и не заменяет footer. Вне TUI таймер не запускается.
- API Pi 0.85.1 содержит `setWorkingMessage`, `addAutocompleteProvider` и `getCommands`, используемые новыми расширениями. Это предварительная проверка API, не подтверждение полной runtime-совместимости.

## Согласованный объём реализации

- Четыре расширения включаются в распространяемый Datalab Kit, с фиксированными версиями и явными ресурсами по схеме ADR 0002.
- `elapsed` и `pi-mention-skill` используют штатные значения по умолчанию. `$` открывает выбор навыков, `/skill:*` скрывается из slash autocomplete; явные пользовательские настройки сохраняются.
- Проверки: загрузка всех четырёх расширений на Pi 0.85.1; модель и reasoning recap; сохранение существующих настроек; таймер полного запроса и восстановление рабочего индикатора; переключение видимости навыка после `/reload` и его явный вызов через `$`.
- Если доступ к реальному Qwen endpoint отсутствует, проверка реального recap отмечается как невыполненная, отдельно от офлайн-проверок.

Источники: npm registry и опубликованные tarball указанных версий; [recap](https://github.com/tifandotme/pi-extensions/tree/master/packages/pi-recap), [pi-gigachat](https://github.com/dev-sergeev/pi-gigachat).

## Границы проверок

Согласованный объём проверяется через интерфейсы Pi: загрузку ресурсов пакета, команды и события расширений, локальный HTTP endpoint провайдера и изолированные пользовательские конфиги. Эти границы используются для TDD; приватные функции сторонних расширений не подменяются.
