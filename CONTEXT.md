# Datalab Kit

Datalab Kit — распространяемый другим пользователям набор дополнений для Pi coding agent.

## Language

**Pi**:
Pi coding agent, к которому пользователь добавляет Datalab Kit.
_Avoid_: pi без уточнения при первом упоминании

**Datalab Kit**:
Набор полезных дополнений для Pi, распространяемый как единое целое. Пользователь добавляет его к уже установленному Pi.
_Avoid_: отдельная конфигурация Pi, замена Pi

**Опасная команда**:
Распознанный вызов удаления локальных данных, любой вызов Hadoop/HDFS либо изменяющая SQL операция или SQL с неизвестным эффектом в поддерживаемом клиенте. Требует усиленного согласования; непрозрачный исполняемый код не становится автоматически частью этой категории.

**Операция чтения**:
Операция получения данных, не изменяющая файлы или состояние сервисов. По умолчанию не требует штатного согласования; принадлежность к защищённой группе важнее этого свойства: чтение через Hadoop/HDFS всё равно требует усиленного согласования.

**Plan mode**:
Режим исследования и согласования плана до перехода к реализации. Допустимость операций в этом режиме определяется политикой планирования, в том числе для проверок и тестов.

**Пользовательское правило разрешений**:
Явно заданное пользователем правило `allow`, `ask` или `deny` для инструмента, команды или доступа к пути. Имеет приоритет над значениями по умолчанию Datalab Kit, но `allow` не отменяет усиленное согласование. Применимый конфигурационный `deny` остаётся окончательным veto.

**Служебный todo**:
Список задач текущей сессии Pi, используемый для планирования и отслеживания работы. Его обновление не является изменением файлов проекта или внешнего сервиса.

**YOLO**:
Штатный режим permission-system для автоматического разрешения обычных операций с решением `ask`. Не отменяет усиленное согласование, применимые `deny` и ограничения Plan mode.

**Сессионное разрешение**:
Решение пользователя в штатном диалоге permission-system, разрешающее соответствующие обычные операции до конца текущей сессии в пределах выбранного правила. Не заменяет усиленное согласование.

**Штатное согласование**:
Обычный путь pi-permission-system: правила, YOLO, judges, диалог одного запуска или сессии и сохранение решений. Сохраняется для вызовов вне защищённых групп.

**Усиленное согласование**:
Отдельное решение человека через крупный красный inline-блок с вводом точного `yes` и отправкой. Не создаёт разрешения на сессию и не передаёт результат в штатный механизм согласования.
_Avoid_: второй штатный диалог, дополнительное сессионное разрешение

**Защищённый вызов**:
Полный неизменённый вызов инструмента, содержащий хотя бы одну опасную команду. Одобряется целиком один раз; изменение входных параметров делает полученное одобрение недействительным.

**Veto**:
Окончательный запрет применимого конфигурационного `deny` или действующей политики Plan mode. Проверяется до усиленного ввода и повторно после ожидания ответа; `yes` его не отменяет.

**SQL с неизвестным эффектом**:
Вход поддерживаемого клиента SQL, для которого анализ не установил только читающий эффект: неизвестный синтаксис, непрочитанный источник, непроверяемая функция или динамический SQL. Требует усиленного согласования, а не автоматического разрешения.

**Человеческий endpoint**:
Доверенный TUI/RPC интерфейс живой корневой сессии, до которого брокер доводит запрос субагента. Ответ родительского агента, judge, YOLO или `allow` не является этим endpoint.

**Адаптер усиленного согласования**:
Версионированная граница между собственными классификатором, UI и брокером Datalab Kit и фиксированным pi-permission-system. Не переносит туда правила опасности или штатные grants; несовместимость блокирует агентские инструменты.
